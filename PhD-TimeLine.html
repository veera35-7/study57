Paper 1 · Foundation
01

A Comparative Study of Machine Learning Algorithms for Information Security Threat Detection

⭐ EasyRole · Baseline detection
Purpose

Starting paper. Establish a baseline by comparing conventional ML algorithms for security-threat detection.

Research Question

Which conventional ML algorithms provide an effective balance between detection performance and computational cost?

Dataset

Primary: CIC-IDS2017. Later add UNSW-NB15.

Difficulty

⭐ Easy — safest starting point. Reuses dataset + pipeline for all later papers.

Algorithms
Logistic RegressionDecision TreeRandom ForestSVMXGBoost

You don't need deep learning here.

Workflow
Dataset→Data Cleaning→ Missing / Invalid Values→Encoding→ Feature Scaling→Train / Test Split→ ML Models→Performance Comparison
Metrics
AccuracyPrecisionRecallF1-scoreROC-AUCFalse Positive RateTraining timePrediction time
Expected contribution: Don't claim a new algorithm. My contribution is a systematic experimental comparison — particularly including computational cost.

Paper 3 · Explainable AI
03

An Explainable Machine Learning Approach for Information Security Threat Detection

⭐⭐ MediumRole · Explainability component
Problem

A classifier may say "Attack". But a security analyst needs "Why did the model classify this traffic as an attack?"

Technologies
SHAPLIMEFeature ImportancePartial Dependence
Research Questions
  1. Which features contribute most to threat classification?
  2. Are explanations consistent across models?
  3. Can XAI help identify potentially misleading features?
  4. Can explanations improve analyst understanding?
Important: IEEE 2022/2023 papers already applied LIME and SHAP to IDS. Don't claim "XAI for IDS is new."
My contribution: Investigate explanation consistency, model comparison, feature stability, and usefulness alongside performance.
Paper 4 · Robustness
04

Evaluating the Robustness of Machine Learning Models for Information Security Threat Detection

⭐⭐⭐ HarderRole · Robustness component
Core Question

Does the model still work when the data changes?

Why It Matters

High benchmark accuracy doesn't automatically mean robust real-world detection.

Experiments

A. Unseen data — Train: Dataset A · Test: Dataset B

B. Noise — Controlled perturbations.

C. Feature changes — Remove / change selected features.

D. Class imbalance — Different attack / normal distributions.

E. Different attack categories — Train on some classes, evaluate generalization.

Measurements
F1RecallFPRPerformance degradationRobustness score
